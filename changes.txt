⏺ Summary of changes since WIP commit (3012bcf708)                                                                                                                                   
                                                                                                                                                                                     
  Problem                                                                                                                                                                            
                                                                                                                                                                                     
  The initial WIP had a working inverted index extension, but the optimizer rule and query execution had critical issues that made the index either unused or inefficient.           
                                                                                                                                                                                     
  Changes and reasoning                                                                                                                                                              
                                                                                                                                                                                   
  ---                                                                                                                                                                                
  1. Switch from optimize_function to pre_optimize_function
                                                                                                                                                                                     
  File: logsearch_extension.cpp                                                                                                                                                    
                                                                                                                                                                                     
  Problem: The optimizer rule never fired. DuckDB's filter pushdown (a built-in optimizer) moves WHERE contains(msg, 'x') from LogicalFilter into LogicalGet.table_filters before    
  extension optimizer hooks run. By the time optimize_function ran, there was no LogicalFilter node to match.
                                                                                                                                                                                     
  Fix: Register as pre_optimize_function which runs before built-in optimizers. The LogicalFilter node still exists at that point.                                                   
   
  ---                                                                                                                                                                                
  2. Flatten AND conjunctions in filter matching                                                                                                                                   
                                                                                                                                                                                     
  File: logsearch_optimizer.cpp
                                                                                                                                                                                     
  Problem: The binder produces WHERE contains(msg, 'x') AND ts > y as a single CONJUNCTION_AND expression, not two separate filter expressions. The optimizer only checked top-level 
  expressions in filter.expressions, never looking inside conjunctions.
                                                                                                                                                                                     
  Fix: Flatten conjunctions into leaf expressions before matching:                                                                                                                 
  for (auto &expr : filter.expressions) {
      if (expr->type == CONJUNCTION_AND) {
          for (auto &child : conj.children) leaf_exprs.push_back(child.get());                                                                                                       
      } else {                                                                
          leaf_exprs.push_back(expr.get());                                                                                                                                          
      }                                                                                                                                                                            
  }                                                                                                                                                                                  
  Both text predicate matching and timestamp extraction now iterate over leaf_exprs.                                                                                               
                                                                                                                                                                                     
  ---                                                                                                                                                                                
  3. Handle CAST-wrapped constants in timestamp extraction
                                                                                                                                                                                     
  File: logsearch_optimizer.cpp                                                                                                                                                    
                                                                                                                                                                                     
  Problem: ts > '2024-01-04' becomes ts > CAST('2024-01-04' AS TIMESTAMP) in the bound plan. The right side is a BoundCastExpression, not BoundConstantExpression. Old code checked  
  expr.type == VALUE_CONSTANT — always false.
                                                                                                                                                                                     
  Fix: Use IsFoldable() to detect any expression evaluable at plan time, then ExpressionExecutor::TryEvaluateScalar() to resolve it to a concrete Value. Handles CAST, implicit      
  casts, constant expressions, etc.
                                                                                                                                                                                     
  ---                                                                                                                                                                              
  4. Fix column name resolution for timestamp column
                                                                                                                                                                                     
  File: logsearch_optimizer.cpp
                                                                                                                                                                                     
  Problem: Used get.names[binding_col_idx] to check if a column is the timestamp column. But binding_col_idx is the position in the projected column list, while names is indexed by 
  physical table column index. These differ when not all columns are projected.
                                                                                                                                                                                     
  Fix: Resolve through column_ids first:                                                                                                                                             
  auto table_col_idx = col_ids[binding_col_idx].GetPrimaryIndex();
  get.names[table_col_idx]  // actual column name                                                                                                                                    
                                                                                                                                                                                     
  ---                                                                                                                                                                                
  5. Replace MARK join with custom table function (index scan)                                                                                                                       
                                                                                                                                                                                     
  Files: New logsearch_index_scan.hpp, logsearch_index_scan.cpp. Modified logsearch_optimizer.cpp.                                                                                 
                                                                                                                                                                                     
  Problem: The MARK join approach (TABLE_SCAN → HASH_JOIN(MARK) → FILTER) read ALL rows from the table. The join only added a boolean column; it didn't reduce the scan. For 10M rows
   with 9K matches, all 10M rows were scanned.                                                                                                                                       
                                                                                                                                                                                     
  Fix: Replace the LogicalGet node entirely with a custom table function LOGSEARCH_INDEX_SCAN that calls DataTable::Fetch() with only the matching row IDs. Row groups containing no 
  matching row IDs are never touched.
                                                                                                                                                                                     
  The optimizer preserves the same table_index so all column bindings in the plan remain valid:                                                                                      
  auto new_get = make_uniq<LogicalGet>(
      get.table_index,       // same — bindings stay valid                                                                                                                           
      index_scan_func,       // our function                                                                                                                                       
      bind_data,             // search parameters                                                                                                                                    
      get.returned_types, get.names, get.virtual_columns                                                                                                                             
  );                                                                                                                                                                                 
  new_get->SetColumnIds(get.GetColumnIds());                                                                                                                                         
  new_get->projection_ids = get.projection_ids;                                                                                                                                    
  filter.children[0] = std::move(new_get);                                                                                                                                           
                                                                                                                                                                                   
  Original filter expressions are kept above for correctness (the index may return superset results — e.g., tokenized contains is wider than substring contains).                    
                                                                                                                                                                                     
  ---                                                                                                                                                                                
  6. Move index query from plan time to execution time                                                                                                                               
                                                                                                                                                                                     
  Files: logsearch_index_scan.hpp, logsearch_index_scan.cpp, logsearch_optimizer.cpp
                                                                                                                                                                                     
  Problem: The optimizer materialized all matching row IDs during planning. This used memory proportional to result set, could be stale if data changes, and the bind data contained 
  pointers/non-serializable data (can't be sent over the network for distributed execution).
                                                                                                                                                                                     
  Fix: Bind data now stores only serializable search parameters:                                                                                                                     
  struct LogsearchScanBindData {
      string catalog_name, schema_name, table_name;  // table location                                                                                                               
      string index_name;                              // index lookup by name                                                                                                        
      vector<string> search_terms;                    // what to search                                                                                                              
      string search_prefix;                                                                                                                                                          
      bool is_prefix;                                                                                                                                                                
      timestamp_t ts_min, ts_max;                     // timestamp bounds                                                                                                          
      bool has_ts_bounds;                                                                                                                                                            
      idx_t estimated_count;                          // for cardinality estimation                                                                                                
  };                                                                                                                                                                                 
                                                                                                                                                                                     
  The actual index query happens in InitGlobal (execution time):                                                                                                                     
  1. Look up table by name → DataTable                                                                                                                                               
  2. Look up index by name from table's index list → LogsearchIndex                                                                                                                  
  3. Query posting lists with search parameters → vector<row_t>                                                                                                                      
  4. Fetch only those rows during scan                                                                                                                                               
                                                                                                                                                                                     
  If the index was dropped between plan and execution, result is empty. The original filter above ensures correctness (falls through to checking every row that passes).             
                                                                                                                                                                                     
  ---                                                                                                                                                                              
  7. Implement TryDelete and VerifyBuffers on LogsearchIndex                                                                                                                         
                                                                                                                                                                                     
  File: logsearch_index.cpp, logsearch_index.hpp
                                                                                                                                                                                     
  Problem: INSERT INTO a table with a logsearch index crashed with "TryDelete not implemented" during transaction rollback. DuckDB's default BoundIndex::TryDelete and VerifyBuffers 
  throw exceptions.                                                                                                                                                                  
                                                                                                                                                                                     
  Fix: Implement as no-ops. TryDelete returns 0 (stale entries remain but post-filter ensures correctness). VerifyBuffers has nothing to verify. For append-only log tables, deletes 
  are rare/irrelevant.

  Architecture after changes                                                                                                                                                       
                                                                                                                                                                                     
  Query: SELECT * FROM logs WHERE contains(message, 'error') AND ts > '2024-01-04'                                                                                                 
                                                                                                                                                                                     
  Optimizer (pre_optimize):
    1. Flatten AND → leaf exprs: [contains(msg,'error'), ts > CAST(...)]                                                                                                             
    2. Match contains → find logsearch index on msg column                                                                                                                           
    3. Extract ts bounds from ts > comparison (via TryEvaluateScalar)                                                                                                                
    4. Check selectivity of 'error' → 10% < 20% threshold → use index                                                                                                                
    5. Store search params in bind data (no row IDs, no pointers)                                                                                                                    
    6. Replace LogicalGet with LOGSEARCH_INDEX_SCAN                                                                                                                                  
                                                                                                                                                                                     
  Execution (InitGlobal):                                                                                                                                                            
    1. Look up table + index by name                                                                                                                                                 
    2. Query inverted index: SearchTerms(["error"], ts_min, ts_max)                                                                                                                
    3. Index skips partitions where ts_max < ts_min → returns subset of row IDs                                                                                                      
                                                                                                                                                                                     
  Execution (Scan):                                                                                                                                                                  
    1. DataTable::Fetch() with batches of row IDs                                                                                                                                    
    2. Only touches row groups containing matching IDs                                                                                                                               
    3. Post-filter applies original contains() + ts > for correctness
                                                                                                                                                                                     
  Plan shape:                                                                                                                                                                        
    AGGREGATE → FILTER [contains(msg,'error') AND ts > ...] → LOGSEARCH_INDEX_SCAN [~25K rows]
